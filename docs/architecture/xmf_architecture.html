SignBridge-XMF: satu model fusion, empat modalitas dari sampel yang sama

Video (keypoint) dan citra kini diambil dari klip WL-BISINDO yang sama, diproses bersama menjadi satu rekaman per sampel bersama pasangan audio dan teks dari konsep yang sama, lalu masuk ke satu Cross-Modal Attention Fusion Transformer. Model yang sama berjalan di browser lewat ONNX Runtime Web.

Cara melaporkan hasil

Metrik utama = V+I (kamera saja), karena itu kondisi nyata pengguna Tuli di depan webcam. Laporkan dua protokol: SD (signer-dependent, sebanding dengan M0 99,1 %) dan SI (penanda 4 tidak pernah dilihat saat training), yang lebih jujur memprediksi uji langsung di browser.

Subset yang memuat audio atau teks dipasangkan di tingkat konsep, sehingga akurasinya tidak boleh diklaim sebagai pengenalan isyarat. Subset itu menunjukkan arah Dengar→Tuli: ucapan guru atau ketikan dipetakan ke konsep yang sama, lalu isyarat rujukan ditampilkan.

Angka di halaman ini (parameter, ukuran, latensi) diukur dari uji asap. Akurasi asli baru ada setelah training di data WL-BISINDO lengkap.

Perintah per tahap

bash scripts/xmf_sync_drive.sh                       # 1 source
python -m signbridge.xmf.ingest                      # 2 ingestion
python -m signbridge.xmf.audio_bank --task gloss     #   bank audio+teks
python -m signbridge.xmf.preprocess --task gloss --workers 4   # 3
python -m signbridge.xmf.train --config configs/xmf_gloss.yaml --protocol sd   # 4-6
python -m signbridge.xmf.train --config configs/xmf_gloss.yaml --protocol si
python -m signbridge.xmf.train --config configs/xmf_gloss.yaml --protocol final
python -m signbridge.xmf.export --ckpt outputs/xmf/XMF_gloss_final/best.pt     # 7
uvicorn server.app:app --port 7860                   # 8 deployment
