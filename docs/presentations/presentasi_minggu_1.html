LATAR BELAKANG & MOTIVASI

Mengapa SignBridge Dibutuhkan?

Barrier Komunikasi Inklusif

Siswa Tuli di ruang kelas reguler sering mengalami keterbatasan interaksi dua arah dengan guru dan teman dengar karena ketiadaan juru bahasa isyarat berdedikasi.

Target: SDG 4.5 & 4.a (Pendidikan Inklusif Berkeadilan).

Kelemahan Solusi Cloud

Sistem penerjemah isyarat konvensional membutuhkan transmisi video mentah ke server GPU eksternal, memicu masalah latensi tinggi (>300 ms), biaya sewa server, dan isu privasi video siswa.

Isolasi Lintas Negara ASEAN

Belum ada jembatan translasi isyarat yang menghubungkan BISINDO (Indonesia) dan FSL (Filipino Sign Language) untuk kolaborasi dan pertukaran pelajar inklusif regional.

Peluang Riset: Membangun sistem inferensi isyarat client-side browser-first menggunakan MediaPipe Holistic + ONNX WebAssembly yang berjalan murni di laptop sekolah tanpa instalasi aplikasi native.

ARSITEKTUR MULTIMODAL

4 Modalitas Input Ruang Kelas SignBridge

Modalitas 1: Video

Kata Dinamis (WL-BISINDO)

Menerjemahkan 32 kata isyarat gerakan utuh berbasis sekuens 86 titik koordinat tubuh (64 frame).

Model: M0 Student Transformer & M1 ST-GCN.

Modalitas 2: Citra

Ejaan Jari (Fingerspelling)

Mengenali bentuk tangan statis untuk 26 abjad Latin (A–Z) dari crop bounding box tangan 224x224 piksel.

Model: MobileNetV3-Small (I1) + Heuristik Geometri.

Modalitas 3: Audio

Pengenalan Suara (ASR)

Menangkap ujaran lisan guru/teman dengar dan mengubahnya ke teks secara langsung untuk ditranslasi ke isyarat.

Engine: Web Speech API & Whisper Fine-Tuning.

Modalitas 4: Teks

Sintesis Kalimat Alami

Mengubah rangkaian kata gloss isyarat menjadi kalimat alami bahasa Indonesia/Tagalog yang terstruktur rapi.

Engine: Rule-Based Template (B0) & IndoT5.

STANDARISASI & REKAYASA PERANGKAT LUNAK

6 Kontrak Antarmuka Lintas Anggota Tim

Setiap anggota tim terikat oleh kontrak antarmuka ketat untuk mencegah divergensi kode:

Kontrak 1: Topologi 86 Node

Mereduksi 543 titik MediaPipe Holistic menjadi 86 titik kanonis: 11 tubuh, 21 tangan kiri, 21 tangan kanan, dan 33 titik wajah ekspresif.

Kontrak 2: I/O Model ONNX

Input wajib berdimensi [B, 64, 86, 3] float32 dan output logits [B, 32]. Ukuran biner wajib di bawah 10 MB.

Kontrak 3: Paritas Python ≡ JS

Pipeline normalisasi bahu dan resampling 64 frame di features.py dan features.js diverifikasi identik numerik (diff < 1e-5).

Kontrak 4: Hand Crop Parity

Crop kotak tangan +25% padding persegi ke resolusi 224x224 diuji identik antara Python dan JavaScript.

Kontrak 5: Model Citra Abjad

Model abjad menerima input tensor citra [B, 3, 224, 224] dan mengeluarkan 26 probabilitas abjad.

Kontrak 6: Backend Hibrida

FastAPI menyediakan endpoint fallback dan ruang kelas WebSocket 2-arah dengan pembatas laju (rate-limiter).

Pipeline Ekstraksi & Normalisasi

  1. Video Input: Frame video 640x480 pada 30 FPS.
  2. MediaPipe Holistic: Deteksi 543 titik skeletal (Pose, Hands, Face).
  3. Seleksi 86 Node: Membuang titik tubuh bawah untuk efisiensi transfer data.
  4. Normalisasi Spasial:
    center = (bahu_kiri + bahu_kanan) / 2
    scale = ||bahu_kiri - bahu_kanan||
    coord = (coord - center) / max(scale, 1e-6)
  5. Resampling Temporal: Interpolasi seragam menjadi tepat 64 frame.

AUDIT & TEMUAN MASALAH

Temuan Masalah Kritis & Audit Kejujuran ML

Berdasarkan audit mendalam, ditemukan kendala nyata di balik metrik akurasi 99%:

1. Signer Leakage (Data Split)

Akurasi 99.13% diperoleh dari Signer-Dependent split di mana 5 penandatangan yang sama muncul di data latih dan uji. Model belum teruji pada penandatangan baru (unseen user via webcam).

2. Kegagalan Model Abjad (I1)

Model MobileNetV3 abjad menghasilkan akurasi uji 3.85% (sama persis dengan tebakan acak 1/26). Model di-bypass di frontend menggunakan aturan heuristik geometri tangan.

3. Fake INT8 & Rule Sentence

Model student_int8.onnx ternyata duplikat identik dari model FP32 (belum kuantisasi nyata), dan penyusunan kalimat masih menggunakan aturan kamus (WER 62.3%).

RENCANA KERJA LANJUTAN

Roadmap Rencana Kerja Minggu 2 & Seterusnya

Minggu 2: Remedi Prioritas P0

  • LOSO Retraining: Terapkan split Leave-One-Signer-Out (Signer 1-3 train, Signer 0 val, Signer 4 test).
  • 3D Skeletal Augmentation: Tambahkan scaling random (0.85–1.15), coordinate jitter, dan temporal speed perturbation.
  • Fix Model Abjad: Latih ulang MobileNetV3 untuk abjad A–Z (target akurasi ≥ 88%).

Minggu 3: Optimasi Kualitas P1

  • Kuantisasi Nyata INT8: Gunakan tool ONNX quantization untuk memangkas biner dari 5,46 MB ke ~1,4 MB.
  • Sintesis Korpus Kalimat: Perluas data teks dari Tatoeba hingga 5.000 pasang gloss-kalimat.
  • Fine-Tuning IndoT5: Mulai eksperimen model penerjemah kalimat neural ringan.

Minggu 4+: Integrasi & Validasi

  • Uji coba langsung pada pengguna tuli dengan protokol pengujian unassisted webcam.
  • Implementasi jembatan bilingual kamus konsep BISINDO ↔ FSL.
  • Penyusunan laporan akhir dan dokumentasi ilmiah.
